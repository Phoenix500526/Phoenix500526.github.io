# Butterfly builds and local preview

The approved direction is a warm technical reading room: Manjusaka's two-column
layout, paper/ink/rust colors, a small curated introduction and quiet reading tools.
The shared theme settings live in `_config.butterfly.yml`. Local and production
overrides are separate. `_config.yml` and the original posts remain unchanged.

## Run

```sh
npm ci
npm test
npm run butterfly:build
npm run butterfly:serve
```

Open http://localhost:4187. The server binds only to 127.0.0.1.
Stop it with Ctrl+C. The serve command builds and serves the generated files.
After editing an override, run `npm run butterfly:build` and refresh the browser.

`npm run build` builds and verifies the production site into `public/` without
deploying. It uses `https://phoenix500526.github.io` and allows indexing; the
local preview keeps localhost URLs and `noindex,nofollow`. Do not upload preview
output. `npm run butterfly:verify` checks both already-built directories.

GitHub Actions uses Node 24, `npm ci`, and `npm run build`. It uploads only
`public/`. **Pushing main or manually running the existing Pages workflow deploys
the site.** Keep commits local until deployment is explicitly approved. The old
`hexo deploy` command is not the Butterfly publication path.

The pinned official npm theme is copied into ignored `themes/butterfly-preview`;
`preview/butterfly` is overlaid on it. CSS, scripts, icon fonts, image zoom, and
MathJax are local. Production pages use a local client to request site visitor
and page-view counts from the official Busuanzi HTTPS endpoint. Failed script
requests retry at most twice; successful requests are never retried. A slow
response can still update the card after its eight-second status timeout.
Preview disables this service.
The website info card shows article count, total word count, visitor count,
page views, and the latest article content update (not the build date).
Unavailable statistics fall back to a status label rather than a zero count.
Preview pages live in `.preview-butterfly`; production pages
live in `public`. Hexo databases and merged configurations live separately in
`.butterfly-cache/preview` and `.butterfly-cache/production`. Every build rejects
an artifact containing `db.json`, `_multiconfig.yml`, or `.env`.
The original `yilia-plus` theme remains available for rollback with `_config.yml`.
The earlier custom `redesign` prototype was archived outside the repository on
2026-11-17, then removed along with its preview commands, configuration, quote
data, and obsolete design documents. Category and tag indexes are generated by
the Butterfly preview theme and need no standalone source pages.

## Design decisions

1. **Atmosphere:** warm paper, typographic hierarchy, compact technical cards.
2. **Palette:** paper `oklch(94.5% .012 78)`, ink `oklch(25% .018 65)`, rust
   `oklch(49% .12 42)`; corresponding warm dark tokens.
3. **Type:** local Iowan/Palatino/Song titles, system sans body, system monospace.
4. **Components:** 10px cards, 6px code blocks, 4px controls; visible focus states.
5. **Layout:** 1180px shell, 280px sidebar, 30px gap; article text around 790px.
6. **Depth:** thin rules and restrained shadow; no backdrop blur or gradients.
7. **Content:** real posts and local diagrams, complete titles, bounded summaries.
8. **Responsive:** sidebar becomes author footer below 900px; at 600px navigation
   collapses, covers move above text, and the article title becomes 28px.
9. **Interaction:** native Butterfly search, TOC, copy, code expansion/fullscreen,
   reading mode and zoom; keyboard enhancements and reduced-motion overrides.
   Light/dark mode follows the OS by default; a manual choice takes precedence
   for Butterfly's native two-day preference lifetime.

Editorial choices live in `butterfly/scripts/phoenix.js`: featured titles,
summaries, selected covers and topic labels. Cards without a cover remain valid.
The skynet category typo is normalized in build data only, with a static redirect
from its old URL. Series lists use
publication order and do not claim a pedagogical chapter order. Article dates
show publication only. Metadata and feeds use explicit `updated` front matter,
falling back to publication time, in the fixed Asia/Shanghai timezone.

The custom templates override homepage, article, navigation, sidebar and footer;
the remaining pages and behaviors come from Butterfly. MathJax uses a small
local v3 configuration to match its pinned runtime instead of upstream's v4/v5
font loading. It loads only for posts with formula delimiters.

Dependencies were updated without forced audit fixes: Markdown and Stylus
renderers are pinned to 7.0.1 and 3.0.1, and compatible transitive security fixes
are recorded in the lockfile. The Markdown upgrade changes one historical
heading ID in the sleep essay; a compatibility anchor retains the old deep link.
Run `npm audit` to recheck current advisories; its result is time-dependent.

`tools/verify-butterfly.cjs` checks article count, required pages, local paths,
indexing policy, canonical/feed origins, content update dates, compatibility
links, and build-state isolation. `npm test` checks menu focus containment and
restoration after button, mask, Escape, and desktop-resize close paths.
The registry regression test also rejects non-official tarball URLs in the
lockfile. Legacy Taobao mirror URLs failed certificate validation on a fresh CI
runner even though local cached installs passed; cold-cache installs must work
against the official npm registry without changing versions or integrity hashes.

## Review before a future deployment

- Read an algorithm post, a long Libevent post, skynet diagrams and a nontechnical
  essay at desktop and 375px widths.
- Check chapter links, search matches/empty results, copy feedback, code expansion,
  image zoom, light/dark mode, menu and pagination.
- Verify all 78 post URLs and image references remain available.
- A future deployment requires a separate instruction and production config review.
